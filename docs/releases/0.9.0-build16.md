## Versioning convention

Use `MAJOR.MINOR.PATCH+BUILD` in Flutter. The portion before `+` is Android's user-visible versionName; the integer after `+` becomes versionCode. Increase the build counter for each distinct Play upload, including a patch or a new major version. Do not reset it when changing the visible version.

For this feature update the public version advances from 0.8.0 to 0.9.0, while build 15 advances to 16. A later bug fix could be 0.9.1+17. Version 1.0.0 is a sensible label for the first stable public release, with the next unused build counter.

References: [Flutter Android releases and versioning](https://docs.flutter.dev/deployment/android#update-the-apps-version-number), [Android version codes](https://developer.android.com/studio/publish/versioning), [Semantic Versioning](https://semver.org/). Microsoft package identities commonly use the separate four-part [Major.Minor.Build.Revision](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/package-identity-overview) format.
